1. Fey.nvim                                                     *fey-fey.nvim*

Fey.nvim is a plugin for Neovim 0.11 and later that makes notes in the Fey
markup language: headings that number themselves, lists, tables, dates and
planning, tasks, an agenda over all your notes, capture and refile, a clock,
queries and databases, links between notes, and export. Everything that has to
be found across files is read from an index of your notes, so it is fast and
nothing has to be open.

To read this documentation inside Neovim run `:Fey help`; the online version is
at <https://fey.github.io>.


QUICK START                                         *fey-fey.nvim-quick-start*

Install the plugin (see Installation <installation.md> for the other package
managers) and set it up:

>lua
    {
      'Loreite/fey.nvim',
      event = 'VeryLazy',
      config = function()
        require('fey').setup({
          fey_court_dir = '~/feyhollow',
          fey_default_notes_file = '~/feyhollow/agenda/inbox.fey', -- optional
        })
        -- Experimental LSP support
        vim.lsp.enable('fey')
      end,
    }
<

Then:

- `<Leader>;c` captures a note, `<Leader>;a` opens the agenda
- `<Leader>;;` opens the navigator on the current file: the court, the hollows, the headings
- `:FeyHollowInit` in a folder makes it a hollow, a folder of notes with an index

Nothing else is needed: the tree-sitter grammar is built the first time a Fey
file is opened, and the index of a hollow is kept up to date in the background.


HOW THE PIECES FIT                           *fey-fey.nvim-how-the-pieces-fit*

- A **note** is a Fey file, `.fey`. Its headings have **signatures**, `I.`, `I.A.`, `II.`, that the plugin keeps in order when headings are moved,
    added or removed.
- A **hollow** is a folder of notes with a `.fey` folder inside, that holds its **vault**: the index (a database of the headings, tags, dates, tasks,
    links, labels, source blocks and footnotes of every note of the hollow).
- The **court** is the folder `fey_court_dir` that every hollow is registered in, with the agenda inbox and the settings of all your notes.
- A **tag** is a piece of syntax that says something about the text around it: a date, a status, a link, a query. The reference of tags <tags.md> lists all of them.
- The words of a heading are its **labels**.

The agenda, the queries, refile, the links and the exports read the vault, so
they work on every hollow of the court, open or not.

COMMANDS AND THE GLOBAL                 *fey-fey.nvim-commands-and-the-global*

The commands:

- `:Fey help` opens this documentation in a tab, `:Fey helpgrep` searches it
- `:Fey agenda {type}` opens an agenda view by its shortcut, without a type it asks; `:Fey capture {type}` the same for a capture template
- `:Fey install_treesitter_grammar` installs the grammar again if there are problems with it
- `:Fey store_link` stores a link to the heading under the cursor (also in the agenda); `:Fey indent_mode` toggles virtual indent
- `:FeyNavigate` opens the navigator; `:FeyHollows` lists the hollows, `:FeyHollowInit` makes the current folder one, `:FeyHollowsPrune` forgets the ones that are gone,
    `:FeyHollowMerge` includes or leaves out a hollow in the merged views
- `:FeyDb`, `:FeyDbHere`, `:FeyDbNew` open and create database views of your notes
- `:FeySettings` shows where the settings of this note come from and what was ignored
- `:FeyVaultReindex` brings the index up to date (with a bang it rebuilds it)
- `:checkhealth fey` checks the installation, the options and the index of every hollow

Every `:Fey` action is also a function of the global `Fey`: `Fey.help()`,
`Fey.agenda()`, `Fey.agenda.m()`, `Fey.capture.t()`.


THE LUA API                                         *fey-fey.nvim-the-lua-api*

The Lua API (`require('fey.api')`) reads the vault and the court, so it works
without opening files; it is described in the help file `fey_api.txt`, `:help
FeyApi`.


HISTORY                                                 *fey-fey.nvim-history*

Fey.nvim began as a port of orgmode to Neovim and kept that history until the
rewrite to the native Fey markup. The orgmode heritage is in the credits
(`legal/`); the changelog starts at the last release before the rewrite.

2. Installation                                             *fey-installation*


REQUIREMENTS                                   *fey-installation-requirements*

- Neovim 0.11 or later (0.12 recommended)
- A C compiler (`cc`, `gcc`, `clang`, `cl` or `zig`) and the `tree-sitter` command, only to build the grammar the first time (the plugin does it, see below)
- `libsqlite3`, the library of the index. The plugin uses it through LuaJIT and has no Lua dependency. If it is not found by the system loader,
    point `vim.g.sqlite_clib_path` at it
- Optional: `pandoc` for exporting to LaTeX, PDF, Word, OpenDocument and EPUB; the `latex` tree-sitter parser for highlighting math; a Nerd Font for the icons of
    checkboxes and concealed queries (without one the icons are plain symbols)


INSTALLATION METHODS                   *fey-installation-installation-methods*

Any package manager works. Some examples:

- lazy.nvim <https://github.com/folke/lazy.nvim> (recommended)

>lua
    return {
      'Loreite/fey.nvim',
      event = 'VeryLazy',
      config = function()
        require('fey').setup({
          fey_court_dir = '~/feyhollow',
        })
        -- Experimental LSP support
        vim.lsp.enable('fey')
      end,
    }
<

- vim.pack (Neovim 0.12 and later)

>lua
    vim.pack.add({
      { src = 'https://github.com/Loreite/fey.nvim' },
    })
    require('fey').setup({ fey_court_dir = '~/feyhollow' })
    vim.lsp.enable('fey')
<

- pckr.nvim <https://github.com/lewis6991/pckr.nvim>

>lua
    require('pckr').add({
      {
        'Loreite/fey.nvim',
        config = function() require('fey').setup({ fey_court_dir = '~/feyhollow' }) end,
      },
    })
<

- vim-plug <https://github.com/junegunn/vim-plug>

>vim
    Plug 'Loreite/fey.nvim'
    
    lua << EOF
    require('fey').setup({ fey_court_dir = '~/feyhollow' })
    EOF
<


THE GRAMMAR                                     *fey-installation-the-grammar*

The first time a Fey file is opened the plugin builds the tree-sitter grammar
of Fey and installs it in its own folder. If that fails (no compiler), or you
want to build it yourself, run `:Fey install_treesitter_grammar`; `:checkhealth
fey` says which grammar is found, where, and whether it is the version the
plugin needs. See Troubleshooting <troubleshoot.md> for problems on Windows.


THE FIRST HOLLOW                           *fey-installation-the-first-hollow*

Open Neovim in a folder of notes (or an empty folder) and run `:FeyHollowInit`.
The folder becomes a hollow: a `.fey` folder is made with the index and the
hollow is registered in the court. From then on the agenda, the queries and the
links read it. The court folder (`fey_court_dir`) is made the first time it is
needed, with the agenda inbox in it; `<Leader>;c` captures a note into it.

Every file ending in `.fey` is a note; a file ending in `.fey_archive` is an
archive. Folders listed in `vault.ignore` are not indexed.

3. Tutorial                                                     *fey-tutorial*

This tutorial builds a small set of notes and uses the features one at a time.
It assumes the plugin is installed and that you have made a hollow (see
Installation <installation.md>). Create a file `projects.fey` in it.


HEADINGS AND LISTS                           *fey-tutorial-headings-and-lists*

A Fey file is made of sections. A heading starts with a signature, which says
how deep it is, and a title:

>fey
      I. Garden
    
    Notes about the garden.
    
      I.A. Vegetables
    
    -  tomatoes
    -  [ ] buy seeds
    -  [x] clear the beds
       -  the east bed first
    
      I.B. Flowers
    
      II. House
<

The signatures `I.`, `I.A.` and `II.` are the plugin's: when you add, move,
promote or demote a heading the others are renumbered. `<Leader>;ih` inserts a
heading after the current one, `<Leader>;*` turns a line or a list item into a
heading (with a count, `3`, at that level) and a heading into text, and `move
subtree up` and `down` swap a heading, with all that is under it, with its
neighbour. `<Tab>` folds a section, `<S-Tab>` cycles the whole file.

A list item starts with a bullet and two spaces. A box after the bullet makes
it a task of its own: `[ ]` is open, `[x]` done, and many other marks (in
progress, important, cancelled, a note, ...) are shown as icons. `<C-Space>`
cycles a box and a parent follows its children.


TAGS                                                       *fey-tutorial-tags*

A tag is a piece of syntax that says something about the text around it. It is
written in brackets with a name, values after commas and keys after a
semicolon:

>fey
    Water the {# hl; fg: green #} tomatoes
    The review is {@ date, 2026-10-07 Wed 09:30 @}.
<

The `#` tags are about the text, the `@` tags are things that are in the text.
A tag is a scope tag (in the line of the text), a line tag (with the words it
is about), a block tag (with an indented body) or a pair tag (an opener, a body
and a closer). The tags page <tags.md> lists every tag with its forms.


DATES, STATUS AND PLANNING           *fey-tutorial-dates,-status-and-planning*

A heading is a task when it has a status. The status, the labels and the
planning tags go with the heading:

>fey
      I.A. {# status, TODO, A #} Plant the tomatoes {# labels, garden, spring #}
    {# scheduled, 2026-10-10 Sat #} {# deadline, 2026-10-15 Thu #}
    {# prop; effort: 2h #}
<

`cit` and `ciT` cycle the state (`TODO`, `DONE`, ...), `ciR` and `cir` the
priority, `<Leader>;is` and `<Leader>;id` set the scheduled date and the
deadline in a calendar, and `<Leader>;sl` changes the labels. With
`fey_conceal_task_tags` the keyword and the labels are shown and the tag syntax
around them is hidden, back on the line of the cursor. A date is changed with
`<S-UP>` and `<C-a>`. Marking a task done writes when (`closed`), and a
repeating date (`+1w`) moves forward instead.


THE AGENDA                                           *fey-tutorial-the-agenda*

`<Leader>;a` opens the agenda: the week with the scheduled tasks, the deadlines
with a warning ahead of them, and what is overdue, from every hollow of the
court. Press `g?` in it for its keys. Move over the days with `f` and `b`,
filter with `/`, change a task in place (state, priority, date, labels, refile,
notes) and jump to it with `<Tab>`. Views by label and by status are there too,
with a small match language, `+garden-spring/TODO`.


CAPTURE AND REFILE                           *fey-tutorial-capture-and-refile*

`<Leader>;c` opens the capture prompt: pick a template, write the note, and it
is filed under the heading the template says (the inbox of the court by
default). `<Leader>;r` refiles the heading under the cursor under another
heading, in this file or another one, in any hollow; `<Leader>;A` archives it.
Templates are options (`fey_capture_templates`).


THE CLOCK AND NOTES                         *fey-tutorial-the-clock-and-notes*

`<Leader>;xi` clocks in on the heading under the cursor, `<Leader>;xo` clocks
out; the clock is written in the logbook of the heading and the time is added
up by the clock report of the agenda and by the clock table. Notes on a
heading, `<Leader>;na`, go into the logbook too when `fey_log_into_logbook` is
on.

>fey
    {# clocktable; span: thisweek; by: heading #}
<

`<Leader>;qq` with the cursor on that tag writes the table of the time clocked
this week after it.


LINKS                                                     *fey-tutorial-links*

A link is a tag: `link` to a file, a url or a section, `section` to a heading
by its signature, and in the line, block and pair forms what is under it is the
link.

>fey
    See {@ link, house.fey; desc: the house; section: II.A. @} and #[ link, https://neovim.io ] Neovim #.
<

`<Leader>;o` follows a link. `<Leader>;ls` stores the heading under the cursor
and `<Leader>;li` inserts a link to a stored heading, a file or a heading of a
file, picked from the index; `<Leader>;lc` lists the links that lead nowhere.
With `fey_id_link_to_fey_use_id` a link follows its heading when it moves.


QUERIES AND DATABASES                     *fey-tutorial-queries-and-databases*

A query is a tag too. It asks the index a question and the result is written
after it, with links to the notes:

>fey
    [ query ]#
       TABLE file.name AS "Note", length(file.tasks) AS "Tasks"
       FROM #garden
       SORT file.mtime DESC
<

`<Leader>;qq` runs it. A `feydb` tag shows a database view, which is edited
with `:FeyDb` (columns, filters, sorts, groups and formulas), as a table
without links. With `conceal: true` a query shows as an icon and its result
alone, and shows everything when the cursor is in it.


FOOTNOTES, COMMENTS AND MATH       *fey-tutorial-footnotes,-comments-and-math*

A footnote is a reference tag and a definition (a pair, block or line tag);
`<Leader>;nf` inserts both and jumps between them. A `comment` tag hides what
it covers from the index and the export, in every form. `math` is LaTeX,
highlighted with the latex parser when it is installed.

>fey
    A claim {@ fn, 1 @}.
    
    [ fn, 1 #]
    The note.
    [# fn ]
    
    #[ comment ] to do: check this #
<


SETTINGS OF A NOTE                           *fey-tutorial-settings-of-a-note*

A note, a hollow or the court can set options of the editor and of plugins with
tags at the top of a file:

>fey
    {# nvim; wrap: false; conceallevel: 2 #}
    {# plugin, fey; fey_highlight_overdue: false #}
<

The options a note may set are a white list, see Configuration
<configuration.md>. `:FeySettings` shows where the settings of the note you are
in come from.


EXPORT                                                   *fey-tutorial-export*

`<Leader>;e` exports the note: Markdown and HTML are written by the plugin,
LaTeX, PDF, Word, OpenDocument and EPUB by pandoc, and an iCalendar file has
the dates. The exports leave out comments and the machinery of the notes
(properties, planning dates, clocks, the logbook).


IMPORT, AND THE COMMAND LINE       *fey-tutorial-import,-and-the-command-line*

Notes you already have come in. `:FeyImport` changes the buffer you are in from
Markdown (Obsidian's too) or org to Fey, in place, and one undo brings the old
text back; `:FeyImport rename` also renames the buffer to `.fey`. For a whole
folder, the command line does it, writing a `.fey` file next to each note, or
over the file with `--write replace`, or over it with the new extension with
`--write rename`:

>sh
    bin/fey import notes/*.md
    bin/fey import --write rename --dry-run vault/**/*.org
    bin/fey export --format html --outdir out notes/*.fey
<

The import reads the files with the tree-sitter parsers of Markdown and org, so
those have to be installed. What cannot come across (highlights, table
formulas, the opener of a tag written in a paragraph) is listed in the notes it
prints. Export from the command line always writes a new file and keeps the Fey
one.

4. Configuration                                           *fey-configuration*


THE SETUP                                        *fey-configuration-the-setup*

Options are given to `setup`. Anything you leave out has its default; the
options are listed below with their type, their default and what they do.

>lua
    require('fey').setup({
      fey_court_dir = '~/feyhollow',
      fey_todo_keywords = { 'TODO', 'WAITING', '|', 'DONE', 'CANCELLED' },
      fey_agenda_span = 'week',
      fey_capture_templates = {
        t = { description = 'Task', template = '  I. {# status, TODO #} %?', target = '~/feyhollow/agenda/inbox.fey' },
      },
      mappings = {
        prefix = '<Leader>;',
        fey = { fey_refile = '<prefix>R' }, -- a mapping is changed here, or `false` to turn it off
      },
    })
<

`setup` checks what it is given and says what is wrong (an option that does not
exist, one that is gone and what replaces it, a value of the wrong type), and
goes on. The old names of options and mappings that were renamed are moved to
the new ones and warned about once. `:checkhealth fey` reports the same.


WHERE SETTINGS COME FROM          *fey-configuration-where-settings-come-from*

The options of the setup are the base. A note can change some of them, and
options of the editor, with tags; so can a hollow and the court, in their file
`config.fey` (in the `.fey` folder), the way a modeline does but with more
control. The layers, later wins, key by key:

- the setup
- the court, `<court>/.fey/config.fey`
- the hollows from the court down to the one of the note, each `.fey/config.fey`
- the tags of the note itself

They are merged into one table before anything is applied; only what differs
from what is applied is changed, and what a note changed is put back when you
leave it. When to apply is `settings.apply_on`: `load`, `enter` (the note
becomes current), `change` (typing, after `settings.debounce_ms`) and `save`;
`<Leader>;?a` applies now and `<Leader>;?t` applies the tag under the cursor.
`settings.cascade = false` makes only the court and the note count.

A note can come from anywhere, so what it may do is a white list:

- the `nvim` tag sets options of the editor that are local to the buffer or the window, and `colorscheme` and `background`; the options that run code are denied (below)
- the `plugin` tag sets the options of this plugin that are on the white list in the table below, and the options of the plugins you registered
- the commands of `buf_enter` and `buf_leave` run commands from the note and so exist only when `settings.hooks` names their keys; leave it unset unless you read every note you open

>fey
    {# nvim; wrap: false; conceallevel: 2 #}
    {# plugin, fey; fey_highlight_overdue: false #}
<

The note should not be opened from a source you do not trust with
`settings.allow` or `settings.hooks` set: a denied option is what makes a note
unable to run code.


THE OPTIONS A NOTE MAY SET      *fey-configuration-the-options-a-note-may-set*

The column "a note may set it" in the table of options is this list. "Takes
effect at once" means the option is read where it is used, so the change is
there as soon as it is applied (and goes back when the note is left); an option
that is not on the list is read when the plugin is set up and cannot be changed
from a note, because it says where things live (the court, the vault), what the
keys are, or runs code. `settings.hot_options` adds names to the list.

Another plugin is configured from notes by registering it:

>lua
    require('fey').setup({
      settings = {
        plugins = {
          -- called with the merged options of every `plugin, mything` tag, when they change
          mything = {
            apply = function(opts) require('mything').setup(opts) end,
            restore = function() require('mything').setup({}) end, -- when no note asks for options any more
          },
        },
      },
    })
<

`apply` gets the options as data (a table), never code from the note; `restore`
puts the plugin back to its own settings when the note that asked is left, and
is optional. A function instead of the table is the same as `apply` alone.


EVERY OPTION                                  *fey-configuration-every-option*

155 options. "A note may set it" is the white list of the `plugin` tag
(`fey.settings.fey_options`): a `plugin` tag, in the court, a hollow or a note,

THE OPTIONS OF THE EDITOR A NOTE MAY NOT SET*fey-configuration-the-options-of-the-editor-a-note-may-not-set*

The options of the editor that a `nvim` tag may not set, because they run what
is in them, call a program or reach outside the editor. `settings.allow` in the
setup opens one by name.

  option             why it is denied
  ------------------ ----------------------

5. Tags                                                             *fey-tags*

A tag is a piece of syntax that says something about the text around it. This
page lists every tag the plugin has; the names are the defaults and each can be
changed with its `*_tag_name` option. A tag is written in one of four forms:

>fey
    a scope tag {# name, value, value; key: value #} inside a line, and {@ name, value @} for things that are in the text
    
    #[ name, value; key: value ] a line tag, the words it is about #
    
    [ name, value; key: value ]#
       a block tag: the indented body belongs to it
    
    [ name, value; key: value #]
    a pair tag, up to the closer
    [# name ]
<

The head is the name, then the values after commas, then the keys after a
semicolon (a backslash escapes a comma, a semicolon or a backslash). The head
ends where the way the tag was opened says: at a sign and the closing bracket
(`#}`, `#]`) for a scope tag and for the opener of a pair tag, at the closing
bracket for a line tag, at the closing bracket and a sign for a block tag.
Every other sign or bracket is a word, so `desc: a > b -> c :)` is a
description. The closing bracket of the opening itself cannot start a word in
the line, block and pair forms (it ends the head, or the text is no tag); in a
scope tag it can. A scope tag applies to the node it is in: its paragraph, its
title or its table cell, the whole list when it is the only content of a list
item, the item when the item has other contents, and the whole file when it is
above the first heading. `Tag.body` is that node, for every handler.

The tags of the plugin:

TAGS OF YOUR OWN, AND TAGS NAMED LIKE HTML*fey-tags-tags-of-your-own,-and-tags-named-like-html*

Any name is a tag: it is indexed (the names and counts are in the index, and
`:checkhealth fey` lists the ones nothing knows), completed, and exported as
the text it holds. To do more:

- editor behaviour: `tag_handlers = { note = { scope_tag = function(tag) ... end } }` in the setup, a function for each form that `Tag.handlers` runs with a `FeyTag`, which has the name, the head
    (`values` and `key_values`), the form (`type`) and the body (`body`)
- export: `tag_exports`, a pattern for each form, where `%s` is what the tag holds (the HTML of the body for the HTML export, the Markdown of it for Markdown, with the HTML around it):

>lua
    require('fey').setup({
      tag_exports = {
        note = {
          block_tag = [[<aside class="note">\n%s\n</aside>]],
          pair_tag = [[<aside class="note">\n%s\n</aside>]],
          line_tag = [[<span class="note">%s</span>]],
          scope_tag = [[<div class="note">\n%s\n</div>]], -- wraps what the tag applies to
        },
      },
    })
<

A form can also be a function `function(body, tag, target)` that returns the
text; a table with the keys `html` and `markdown` gives each target its own
forms; a form named `default` is the one for the forms that are not there.

A tag named like an HTML element (`span`, `mark`, `kbd`, `sub`, `sup`, `div`,
`details`, `summary`, `blockquote`, ...) in the line, block and pair forms is
that element in the exports, with its keys as attributes (event attributes and
`javascript:` values are dropped). When a name is taken (by the plugin, by a
`tag_exports` entry or a `tag_handlers` entry) it keeps its meaning and the
weaker name ends with an underscore: `section_` is the HTML `section` where
`section` is the link to a heading, `table_` the HTML `table`, and with a `div`
of your own `div_` is the HTML `div`. Name your own tags with this in mind: a
name that ends with `_` is read as the element without it.

7. Plugins and tools                                   *fey-plugins-and-tools*

Fey works on its own. These are the tools it uses when they are there.


COMPLETION                                  *fey-plugins-and-tools-completion*

Inside a tag the completion knows where it is: the name, a value, a key, the
value of a key. It is offered through four doors, which all give the same
answers:

- `omnifunc` (`<C-x><C-o>`), set for Fey buffers
- blink.cmp <https://github.com/Saghen/blink.cmp>: the source `fey`, `sources.per_filetype = { fey = { 'fey', 'buffer' } }` with the provider `fey.fey.autocompletion.blink`
- nvim-cmp <https://github.com/hrsh7th/nvim-cmp>: the source `fey` is registered when nvim-cmp is there: `sources = { { name = 'fey' } }`
- `vim.lsp.enable('fey')`: the experimental language server, which also gives symbols, references and links

The trigger characters are `,` `;` `:` space `@` `#` `[` and `/`.


THE LATEX PARSER                      *fey-plugins-and-tools-the-latex-parser*

The text of a `math` tag, and fenced blocks named `latex`, are highlighted with
the `latex` tree-sitter parser when it is installed (nvim-treesitter installs
it). Without it they are plain text.


PANDOC                                          *fey-plugins-and-tools-pandoc*

`pandoc` writes LaTeX, PDF, Word, OpenDocument and EPUB from the Markdown that
Fey writes. Install it from your system's packages. It is the only external
program the plugin calls for exports.


ICONS                                            *fey-plugins-and-tools-icons*

Checkboxes and concealed queries show icons. With a Nerd Font and
`nvim-web-devicons` they are Nerd Font glyphs, otherwise plain Unicode symbols;
`fey_checkbox_icons`, `fey_checkbox_icon_overrides` and `fey_conceal_icons`
change them.


PLUGINS OF YOUR OWN                *fey-plugins-and-tools-plugins-of-your-own*

A plugin can be configured from notes with a `plugin` tag when it is registered
(`settings.plugins`, see Configuration <configuration.md>), and a plugin can
add tags with `tag_handlers` and `tag_exports` (see Tags <tags.md>). The Lua
API (`require('fey.api')`) is for plugins that read the notes: the vault, the
court, headings, links and the agenda; it is in `:help FeyApi`.

8. Troubleshooting                                       *fey-troubleshooting*

Run `:checkhealth fey` first. It checks the grammar, the options of the setup,
and for every hollow the state of the index, the files that are out of date or
did not parse, and the tags nothing knows.


NOTHING IS HIGHLIGHTED, OR I GET TREE-SITTER ERRORS*fey-troubleshooting-nothing-is-highlighted,-or-i-get-tree-sitter-errors*

The grammar may not be installed or is out of date. `:checkhealth fey` says
which. Run `:Fey install_treesitter_grammar` to build and install it again; it
needs a C compiler and the `tree-sitter` command. The error `No parser for
language "fey"` means the same.


THE GRAMMAR FAILS TO BUILD ON WINDOWS*fey-troubleshooting-the-grammar-fails-to-build-on-windows*

`.../fey/parser/fey.so is not a valid Win32 application` comes from the wrong C
compiler. The first of `cc, gcc, clang, cl, zig` that is found is used; to
choose one, set the list before `setup`:

>lua
    require('fey.utils.treesitter.install').compilers = { 'clang' }
    require('fey').setup()
<

Restart Neovim and run `:Fey install_treesitter_grammar`.


THE AGENDA, A QUERY OR THE LINKS ARE EMPTY OR OLD*fey-troubleshooting-the-agenda,-a-query-or-the-links-are-empty-or-old*

They read the index of the hollows. `:checkhealth fey` lists a stale index;
`:FeyVaultReindex` brings it up to date and `:FeyVaultReindex!` rebuilds it. A
folder is only a hollow when it has a `.fey` folder (`:FeyHollowInit`) and is
registered in the court (`:FeyHollows` lists them). Folders named in
`vault.ignore` are not indexed. If the library of the index is not found, set
`vim.g.sqlite_clib_path`.


INDENTATION IS NOT WORKING    *fey-troubleshooting-indentation-is-not-working*

Do not override `indentexpr` in Fey buffers with another plugin
(nvim-treesitter's indentation, for one).


DATES ARE NOT IN ENGLISH, OR CHINESE CHARACTERS ARE BROKEN*fey-troubleshooting-dates-are-not-in-english,-or-chinese-characters-are-broken*

Dates are made with the date functions of Lua, which read your locale. In your
`init.lua`:

>lua
    vim.cmd('language en_US.utf8')
<

`:language` and `<Tab>` list the locales you have; use `zh_CN.utf8` for
Chinese.


LINKS, QUERIES AND CHECKBOXES ARE NOT HIDDEN OR ARE NOT ICONS*fey-troubleshooting-links,-queries-and-checkboxes-are-not-hidden-or-are-not-icons*

Concealment uses the conceal feature of Vim: set `vim.opt.conceallevel = 2`.
Concealed tags come back on the line of the cursor unless `concealcursor` says
otherwise. Icons are Nerd Font glyphs when `nvim-web-devicons` is installed (or
`fey_checkbox_icons = 'nerd'`), plain symbols otherwise; `fey_checkbox_icons =
'unicode'` forces them.


A NOTE'S SETTINGS DO NOTHING, OR SOMETHING IS IGNORED*fey-troubleshooting-a-note's-settings-do-nothing,-or-something-is-ignored*

`:FeySettings` shows where the settings of the note come from and what was
ignored, with the reason: an option that is not local to the buffer or the
window, one that runs code (denied unless `settings.allow` names it), a plugin
that is not registered, an option of this plugin that is not on the white list.
The options that are, are in Configuration <configuration.md>.


EXPORTING TO PDF, WORD OR LATEX FAILS*fey-troubleshooting-exporting-to-pdf,-word-or-latex-fails*

Those formats go through `pandoc`: it has to be in the `PATH`, and a PDF needs
a LaTeX engine as well. Markdown, HTML and iCalendar need nothing. A file that
is all commented has nothing to export.


JUMPING TO A PATH DOES NOT WORK ON WINDOWS*fey-troubleshooting-jumping-to-a-path-does-not-work-on-windows*

Paths are written with backslashes by default. Use forward slashes with
`vim.opt.shellslash = true`.


A WARNING ABOUT AN OPTION WHEN NEOVIM STARTS*fey-troubleshooting-a-warning-about-an-option-when-neovim-starts*

`setup` names what it does not know: `fey_tpyo is not an option` is a typo, and
`... is gone: ...` is an option that was removed and says what replaces it. An
option or mapping that was renamed is moved to its new name and warned about
once; the old names are removed after a release.

9. Contributing                                             *fey-contributing*

Thanks for wanting to help out with fey.nvim, we appreciate the effort!


REPORTING BUGS AND FEATURES     *fey-contributing-reporting-bugs-and-features*

Please always search the issue tracker
<https://github.com/Loreite/fey.nvim/issues> before reporting anything. If the
bug or the feature has been reported, continue the conversation on that issue.
Bugs get the highest priority. `:checkhealth fey` is the first thing to put in
a bug report, with a minimal note that shows the problem.


DOCUMENTATION                                 *fey-contributing-documentation*

If you spot something missing in these docs, a pull request is welcome. The
docs are Fey files (`docs/*.fey`): the reference of the options, the tags and
the mappings is generated from the code, so a change to one of those is made in
the code (the options in `lua/fey/config`, the tags in `lua/fey/docs/tags.lua`)
and the page is rebuilt with `scripts/gen_docs.lua`. `scripts/build_docs.sh`
makes the help files (`doc/fey.txt`) from the pages.


DEVELOPMENT                                     *fey-contributing-development*


Philosophy                                                    *fey-Philosophy*

The plugin works on the index of the notes (the vault) and on the tree of the
buffer, not on text: a feature that spans files reads the vault, a feature on
the text under the cursor reads the tree. The words are the words of Fey, see
the glossary below. Options are `fey_snake_case`.


Local development                                      *fey-Local-development*

Install StyLua <https://github.com/JohnnyMorganz/StyLua> for formatting.
`scripts/install_hooks.sh` installs a pre-commit hook: the staged Lua files
have to be formatted (it tells you which to format, it does not touch your
files) and the fast tests have to pass.


Tests                                                              *fey-Tests*

`scripts/test.sh` runs everything: every suite in `tests/` (one Neovim each, in
a temporary court and hollow), the parse of the README and the roadmap, the
screen checks (a real Neovim in tmux) and the corpus of the grammar.
`scripts/test.sh --fast` skips the screen checks and the corpus;
`scripts/test.sh agenda export` runs only those suites. Set `FEY_PARSER` to the
built `fey.so`; the corpus needs `tree-sitter` and `FEY_GRAMMAR`, the folder of
tree-sitter-fey.

- A suite is a Lua file in `tests/` that prints `name: N checks, M failures` and quits with a failure when M is not 0
- `tests/modules.lua` loads every module; `tests/tags_matrix.lua` takes every tag in every form through parse, index, handler, export and completion, and fails when a tag of the table of tags has no sample
- A change to the grammar needs a case in `test/corpus` of tree-sitter-fey (`tree-sitter test -u` writes the expected tree; read it)
- `tests/docs.lua` fails when the generated parts of the docs are out of date or a tag or an option is missing from them


Code                                                                *fey-Code*

If you prefer working on an issue that has been reported, please leave a
comment voicing your interest. Document new code with EmmyLua annotations
<https://emmylua.github.io/annotation.html>.


Parser                                                            *fey-Parser*

Parsing is done with the builtin tree-sitter and the tree-sitter-fey
<https://github.com/Loreite/tree-sitter-fey> grammar.


Commits                                                          *fey-Commits*

Follow the Conventional Commits <https://www.conventionalcommits.org/>
specification: `feat: add new feature`, `fix: correct bug`, `docs: update
documentation`.


GLOSSARY: SAY FEY, NOT ORG       *fey-contributing-glossary:-say-fey,-not-org*

The code, the options and the docs were written for orgmode and some words mean
something else in Fey. The worst is "tag": in org it is a word of a headline,
in Fey it is a piece of syntax, and the words of a heading are labels.
`scripts/terms.lua --check` fails when a file uses an old word more often than
it did; `scripts/test.sh` runs it.

  org word                           Fey word                        where it shows
  ---------------------------------- ------------------------------- ---------------------------------------------------------
  headline                           heading                         comments, docs, config text
  tags of a headline, :a:b:          labels                          get_labels, set_labels, add_label, labels_to_string
  (the same, in options)             labels                          fey_use_label_inheritance, fey_agenda_remove_labels
  tag (the word, syntax)             tag                             stays, and only means the syntax
  stars                              signature                       fey_hide_leading_signature
  headline text, item                title                           FeyFile:get_title
