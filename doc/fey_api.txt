1. Overview                                                   *fey-api-overview*

The API reads the vault index: a SQLite database (`.fey/vault.db`) with the
metadata of every Fey file below a directory that contains a `.fey/` folder. It
is built from the syntax tree and refreshed when the cwd changes, when a file is
saved and by |FeyApiVault:reindex()|. Writes go to the Fey files themselves and
the index follows.

>lua
    local fey = require('fey.api')
    local vault = fey.current_vault()
    if vault and vault:wait() then
      for _, file in ipairs(vault:files_with_label('design')) do
        print(file.path, file:property('rating'))
      end
    end
<

Terminology: a "tag" is always a Fey syntactic tag. Topical categories are called
"labels".

2. Module functions                                             *fey-api-module*

`require('fey.api')`

vault({path?})                                                  *fey.api.vault()*
    The vault that holds `path` (default: the current buffer), else the vault of
    the cwd. Returns |FeyApiVault| or nil.

current_vault()                                         *fey.api.current_vault()*
    The vault of the cwd. Returns |FeyApiVault| or nil.

init_vault({dir?})                                        *fey.api.init_vault()*
    Create a `.fey` directory in `dir` (default: the cwd) and index it.

file({path})                                                    *fey.api.file()*
    A |FeyApiFile| by vault relative or absolute path, or nil.

current()                                                    *fey.api.current()*
    The |FeyApiFile| of the current buffer (errors for other filetypes).

query({src}, {opts?})                                          *fey.api.query()*
    Run a query-language query in the current vault and return its result:
    `type` ("table" or "list"), `count`, and `headers` and `rows` (table) or
    `items` (list). `opts.this` is the vault relative path of the note the query
    lives in.

query_lines({src}, {opts?})                              *fey.api.query_lines()*
    The query as the lines of Fey source that a `query` tag writes.

on({event}, {callback})                                           *fey.api.on()*
    Subscribe to a vault event, see |fey-api-events|. Returns an autocmd id.

link_text({target}, {opts?})                               *fey.api.link_text()*
    `{@ link, target; desc: ...; section: ... @}`. `opts` has `desc`, `section`.

section_text({signature}, {file?}, {n?})                *fey.api.section_text()*
    `{@ section, signature, file, n @}` (N is written as `n:` without a file).

insert_link({target}, {opts?})                           *fey.api.insert_link()*
    Insert a link tag at the cursor. Absolute paths inside the vault become
    vault relative.

insert_section_link({signature}, {file?}, {n?})   *fey.api.insert_section_link()*
    Insert a section tag at the cursor.

follow()                                                     *fey.api.follow()*
    Follow the link or section tag under the cursor.

3. FeyApiVault                                                  *fey-api-vault*

Fields: ~
    {root}  (string)  folder that holds `.fey`
    {dir}   (string)  the `.fey` directory

FeyApiVault:state()                                       *FeyApiVault:state()*
    `idle`, `indexing`, `ready` or `error`.

FeyApiVault:revision()                                 *FeyApiVault:revision()*
    A counter that changes whenever the index changes. Use it as a cache key.

FeyApiVault:wait({timeout?})                               *FeyApiVault:wait()*
    Block until the index is ready (default 10000 ms). Returns a boolean.

FeyApiVault:reindex({opts?}, {on_done?})                *FeyApiVault:reindex()*
    Update the index. `{ full = true }` rebuilds it. `on_done(stats, err)`
    receives `total`, `indexed`, `removed` and `failed`.

FeyApiVault:index_path({path})                        *FeyApiVault:index_path()*
    Re-index one file right now (absolute path).

FeyApiVault:query({sql}, {params?})                       *FeyApiVault:query()*
    Run SQL against the index and get a list of rows (tables keyed by column).
    Parameters are named: `:name` in the SQL, `{ name = value }` in `params`.

FeyApiVault:files()                                       *FeyApiVault:files()*
    All files, ordered by path, as |FeyApiFile|.

FeyApiVault:file({path})                                   *FeyApiVault:file()*
    One file by vault relative or absolute path.

FeyApiVault:files_with_label({label})           *FeyApiVault:files_with_label()*
    Files with a label. Case insensitive, `a` also matches `a/b`.

FeyApiVault:files_with_property({name}, {value?})
                                              *FeyApiVault:files_with_property()*
    Files whose document data has the property (and the given value).

FeyApiVault:labels()                                     *FeyApiVault:labels()*
    Every label with the number of files using it: `{ label, count }`.

FeyApiVault:tags({name})                                   *FeyApiVault:tags()*
    Every use of a tag name: `path`, `line`, `kind`, `vals`, `attrs`.

FeyApiVault:headings({path})                           *FeyApiVault:headings()*
    The heading rows of a file, `data` decoded.

FeyApiVault:links({path})                                 *FeyApiVault:links()*
    Links and section tags written in a file.

FeyApiVault:backlinks({path}, {signature?})           *FeyApiVault:backlinks()*
    Links that point at a file, or at a heading of it. Only the tokens of the
    signature count (`I.A.`, `I,A,` and `I:A` are the same).

FeyApiVault:databases()                               *FeyApiVault:databases()*
    Names of the databases in `.fey/dbs`.

FeyApiVault:database({name}, {view?})                  *FeyApiVault:database()*
    Rows of a database view as it shows them: `{ columns, props, rows, total }`.
    `rows` holds query-language values (dates, links, lists ...).

FeyApiVault:run_query({src}, {opts?})                  *FeyApiVault:run_query()*
    Same as |fey.api.query()| for this vault.

4. FeyApiFile                                                    *fey-api-file*

Fields: ~
    {vault}   (FeyApiVault)
    {path}    (string)    relative to the vault root
    {abs}     (string)    absolute path
    {title}   (string)    the `title` data key, else the first heading, else the name
    {mtime}   (integer)   milliseconds, when it was indexed
    {size}    (integer)
    {errors}  (string[]?) problems found while indexing

Lazy fields (read from the index on first access): ~
    {data}       the document data value (usually a table)
    {labels}     (string[])
    {headings}   (FeyApiHeading[])
    {tags}       every tag of the file
    {links}      links and section tags written in the file
    {backlinks}  links from other files to this file

FeyApiFile:property({key})                              *FeyApiFile:property()*
    A top level property (key of the document data).

FeyApiFile:set_property({key}, {value})             *FeyApiFile:set_property()*
    Write a property into the file and update the index. `nil` removes it.
    Values are strings, numbers, booleans or lists of those. The value is written
    where the property already is (a `table` tag attribute, a bullet of its
    body, a `{# value #}` section). New properties are added to the first
    `table` tag, or as a `[ table #]` block at the top. Returns `ok, err`.
    If the file is open in an unmodified buffer, it is edited and written.

FeyApiFile:remove_property({key})                *FeyApiFile:remove_property()*
    Same as `set_property(key, nil)`.

FeyApiFile:add_label({label})                            *FeyApiFile:add_label()*
FeyApiFile:remove_label({label})                      *FeyApiFile:remove_label()*
    Edit the `labels` property. Labels written as `{# labels, ... #}` tags are
    not touched.

FeyApiFile:reload()                                          *FeyApiFile:reload()*
    Drop what was read, so the next access reads the index again.

FeyApiFile:read()                                              *FeyApiFile:read()*
    The source text (from the buffer when the file is open).

FeyApiFile:open({mode?})                                       *FeyApiFile:open()*
    `split`, `vsplit`, `tab` or `current` (default).

5. FeyApiHeading                                              *fey-api-heading*

Fields: ~
    {file}, {ord}, {parent_ord}, {level}, {signature}, {title}, {path}
    {line}, {end_line}  1-based, `end_line` includes subsections
    {data}              data of a section without subsections
    {labels}            labels given inside the section

FeyApiHeading:parent()                                  *FeyApiHeading:parent()*
FeyApiHeading:children()                              *FeyApiHeading:children()*
FeyApiHeading:backlinks()                            *FeyApiHeading:backlinks()*
FeyApiHeading:jump({mode?})                              *FeyApiHeading:jump()*
    Open the file and put the cursor on the heading.

==============================================================================
6. Events                                                      *fey-api-events*

`User` autocmds (`vim.api.nvim_create_autocmd('User', ...)`, or |fey.api.on()|):

    `FeyVaultIndexed`      a scan finished. `data = { root, stats }`
    `FeyVaultFileIndexed`  one file was re-indexed. `data = { root, path }`

==============================================================================
7. The index schema                                            *fey-api-schema*

All `path` columns are relative to the vault root; JSON columns hold JSON text.

    files       id, path, mtime, size, title, data (JSON), errors (JSON), indexed_at
    headings    file_id, ord, parent_ord, level, signature, title, path, line,
                end_line, data (JSON)
    tags        file_id, heading_ord, kind, name, line, vals (JSON), attrs (JSON)
    links       file_id, heading_ord, kind, target, target_file, target_sig,
                description, line, meta (JSON)
    labels      file_id, heading_ord, label
    properties  file_id, name, value (JSON): the top level keys of the data

`heading_ord` is NULL for entries outside any section. `target_sig` is the
signature as tokens joined by dots (`I.A.` is stored as `I.A`).
